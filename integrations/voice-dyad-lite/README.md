# Installed producer-panel Dyad integration

The producer requested that the Live Show panel's existing **Dyad** checkbox use voice-dyad-lite after approving the fixed-GOLD-line audition. ON selects the approved saved voices locally; OFF retains the installation's standard voice choices. GOLD and the original ARGUE writer run in both positions. No second writer call, model reload, new audio owner, or generation-setting change is added.

`installed.patch` records exactly seven runtime files against the 2026-10-17 installation. `manifest.json` lists their before/after byte hashes and the four frozen GOLD hashes. The installation has newer host/panel behavior than this branch's frozen GOLD base, so this patch is an integration artifact for that exact source, not a patch to apply blindly to the older repository host. It preserves the newer chat, blank-donation, STOP, presentation, singing and native-stage paths. Source text in the patch uses LF; deployed-file hashes describe the actual Windows bytes.

The host uses `createVoiceDyadControl` and a dynamic provider callback. Its prior full-dyad writer routing is removed. The existing `dyadEnabled` flag persists the selection; changing it while idle does not replace a running service. A response retains one selection even if its first voice is admitted during a pending save. Save failures restore the old in-memory selection. All required voice categories must be advertised by the resident worker before the option is available.

Deployment backed up every replaced file and private configuration outside this repository, verified the source hashes before copying, and checked GOLD again afterward. A stale empty donation-ledger lock from the stopped show was backed up only after shutdown and exclusive-open checks; the ledger hash was unchanged. No private configuration, backups, voice recordings, model files or access tokens are included here.

Validation: 302 repository Node tests, 331 staged-installation Node tests, and 13 final targeted tests passed. The unchanged Python selector previously passed eight tests. The installed authenticated control persisted OFF and ON, made zero writer calls, and reused the same voice worker and player. The final state was Dyad ON, Live Show/browser output, muted and idle with chat and paid intake off. `runtime-verification.json` is a sanitized receipt; actual audible comparison was the preceding six-line isolated audition, not the toggle test.

This is an authorized local deployment recorded in an unmerged draft PR. It is not an automatic installer for other source versions. To reproduce elsewhere, first match the manifest's baseline hashes, apply/review the overlay in a staging copy, preserve native line endings, run that installation's tests, and verify the final hashes before replacing an idle host. Rollback uses the locally retained original seven-file set (three paths were newly added).
